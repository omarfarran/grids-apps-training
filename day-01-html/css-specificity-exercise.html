Predict, inspect, then explain

This separate Day 3 exercise intentionally includes conflicting rules. Open assets/css/specificity-exercise.css, predict the winning color, then inspect each sample in your browser's developer tools.

All rules use the same author origin and no cascade layers. Compare specificity first; use source order to break a tie. Inherited values apply when the child has no declaration for that property.

1. Type, class, and ID selectors

Sample A: only the mark type selector matches.

Sample B: the type and class selectors match.

Sample C: type, class, and ID selectors match.

Which rule wins for each sample? Does moving the class rule below the ID rule change Sample C?

Reveal the explanation
  • A uses the secondary color: mark has specificity (0, 0, 1).
  • B uses the accent color: .priority-sample has specificity (0, 1, 0).
  • C uses the primary color: #specificity-winner has specificity (1, 0, 0), even though the class rule appears later.

2. Equal specificity and source order

Sample D: two rules target this same class.

Predict the color. Swap the two .source-order-sample rules in the exercise stylesheet and reload.

Reveal the explanation

Both rules have specificity (0, 1, 0). The later rule wins, so D starts with the accent color. Swapping the rules makes the primary color win.

3. Inheritance and a direct declaration

Sample E: I inherit the parent's secondary color and italic font style.
Sample F: my class declares a primary color and normal font style.

Remove the inheritance-override class from F in developer tools. What changes?

Reveal the explanation

E has no direct declarations for color or font-style, so it inherits them. F has direct declarations, which replace inherited values. Removing its class makes F inherit the same values as E.

Debugging checklist

  1. Find all rules matching the element.
  2. Compare type (0, 0, 1), class (0, 1, 0), and ID (1, 0, 0) specificity.
  3. If specificity is equal, check which rule appears later.
  4. If there is no direct declaration, inspect the inherited value.
  5. Explain the winning rule before changing it.
